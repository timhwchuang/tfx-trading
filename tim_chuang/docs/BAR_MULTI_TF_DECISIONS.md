# 多週期 K 棒 / 交易日 — 已收斂決策

> 來源：2026-07 設計討論（BarStore / 1m SSOT / 日 K / trade_day）。  
> 後續實作與 code review **以本文為基準**；若要改規則，先改本文再改 code。

## 1. 分層職責（程式判斷要清晰）

| 層 | 職責 | 不做 |
|----|------|------|
| **1m 檔案鏈（行情 SSOT）** | 讀檔、組高週期、組日 K | 不猜「是不是假日」 |
| **trade_day（校驗）** | 驗證「應不應該有檔」；缺了 → 告警 / fail / 補抓 | **不**當日 K 拼接主鍵、不拿來 hard-stitch |

```text
應有檔且檔在     → 正常
應有檔卻沒有     → 資料事故（不可當放假縫下去）
不應有檔且沒有   → 正常休市
不應有檔卻有     → 異常，另查
```

## 2. 1 分 K 與 timestamp 語意

- 看盤慣例：**當分鐘走完才收一根**；`timestamp` = **收 K 時間**。
- **08:45 開盤沒有「已收的 08:45 分 K」**；第一根已收通常是 **08:46**。
- 例：第一根 1h = 分 K `08:46～09:45`（含）→ 1h label **09:45**；下一根從 **09:46**。
- 半開區間 `[08:45:00, 09:45:00)` 僅是成交時段的數學切法，**不是** x 軸標籤；規格用 close label 寫即可。
- 夜盤若同樣無「已收 15:00」，第一根分 K 從 **15:01** 類推。

## 3. Session（時鐘）

- 日盤：`08:45–13:45`（錨 08:45；實際 1m 從第一根有的分 K 起）。
- 夜盤概念：`15:00–05:00`（跨午夜連續想；1/5/15/30/60 在午夜切開結果通常相同）。
- 檔案命名「一天」：依檔名日曆鍵；讀單檔時跨日 4h 可能缺一根。

## 4. 高週期（皆從 1m 聚合；歷史不完整 → 捨棄）

- 週期：`1 / 3 / 5 / 15 / 30 / 60(=1h) / 4h`（+ 日 K 另節）。
- **3m 與 5m 同一概念**：session 錨、close label、尾不足丟。
- **60m ≡ 1h**（同一對齊）。
- 歷史 / 畫圖 / 回測窗口：左右或尾段 **湊不滿整根 → 不輸出**。
- Live：forming bar 可 push；與「歷史只認 closed」分開，勿同一條 if。
- 中間缺 1m（斷線洞）：建議 **closed 需滿額才輸出**（與邊緣捨棄一致）；若放寬須另寫。

### 4h 完整集合（close-label 口語）

約四根：

1. `08:46～12:45`（日盤）
2. `15:01～19:00`
3. `19:01～23:00`
4. `23:01～03:00`（**跨日**，單日曆檔通常畫不出 → 需次日資料才閉合）

尾段不足（如 `12:45–13:45`、`03:00–05:00`）捨棄。

## 5. 日 K 與 trade day（制度）

期交所盤後語意（實作應對齊）：

> 盤後與 **次一營業日的一般交易時段** 視為 **同一交易日**；  
> 每日結算價在一般交易時段公告。

因此：

| 夜盤 | 歸屬 trade day |
|------|----------------|
| 正常週一 15:00～週二 05:00 | 週二 |
| 正常週五 15:00～週六 05:00 | **週一**（下一個有日盤的營業日） |
| 週五國定假日時：週四 15:00～週五 05:00 | **週一**（週五非營業日、週五 15:00 不開） |
| 過年後第一天 | 年前最後有檔日之夜盤（若有）+ 開紅盤日盤 |

**禁止**：用「任意更早的有資料日」在資料洞時 silent 錯縫（缺檔若其實有開市，prev-file 會縫錯夜盤）。

### 5.1 組日 K（行情路徑 — 主規則）

前提：檔案完整時「有檔 ≈ 有市、缺檔 ≈ 休市」。

```text
日 K(T) = prev_existing_file(T) 的 15:00–05:00（有才併）
        + T 的日盤 08:45–13:45
        + 磁碟偶見結算尾棒 13:46 / 05:01（有才併；Close 取含 13:46 的最後一根）
夜段空 → 允許只有日盤（長假後常見）
```

- **5 / 15 / 30 / 60 / 4h 不吃尾棒**：那些格子仍停在 13:45 / 05:00。
- 日盤完整性仍以 `08:46–13:45` 滿額為準；13:46 / 05:01 是可選附加，不是缺一分就不出棒。

- **不要**用 trade_day 當拼接主鍵。
- **要**用 trade_day 驗證：應有檔卻沒有 → fail，不可當放假。

### 5.2 trade_day（校驗路徑）

- 來源：`trade_days/*.json` 等曆 + 必要時臨時休市公告。
- 只做存在性 / 完整性校驗。
- 颱風等：以交易所當次公告為準，不完全等於國定假日規則。

## 6. 建議程式形狀

```text
load_bars(date)           # 有就用，沒就空
daily_k(T)                # prev_existing 夜 + T 日
resample(tf, window)      # 1m → 高週期；未滿不輸出
assert_files(trade_days)  # 該有沒有 → 錯誤路徑
```

行情路徑與校驗路徑 **不纏在同一條 if**。

## 7. 刻意未寫死 / 實作時再釘

- 1m 檔結構：日曆日檔（含當日 15:00 起夜盤）vs trade-date 打包檔 — **擇一**，算法細節略有不同；目前討論假設 **可對「上一檔的 15:00–05:00」取值**。
- OHLCV 聚合：`amount` 是否 sum（預設 sum）。
- 檔案路徑與命名 convention（與 `kbars_data/` 現況對齊時再定）。

## 8. 一句話總覽

```text
1m 檔 = 行情 SSOT
高週期 / 日 K = 從檔案鏈組（日 K 用上一有檔夜盤 + 當日日盤）
trade_day = 只驗證檔該不該存在
歷史半根丟；live forming 另議
timestamp = 收 K 時間；開盤無幽靈 08:45 空 K
```
